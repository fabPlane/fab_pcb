# Four-layer BGA escape fixtures

B1 and B2 contain 100 BGA balls connected to 100 perimeter pads on a 50 × 50 mm
board. Both use four signal copper layers and the same seed-19 shuffled target
assignment. B1 has 0.8 mm pitch and 0.35 mm square ball pads; B2 has 0.65 mm pitch
and 0.25 mm pads. These synthetic MIT fixtures need no footprint libraries.
Parameters are recorded in `manifest.json`; generated geometry is checked in.

All 200 pads are front-side SMD. There are no tracks, vias, zones, keepouts,
differential pairs or length constraints. Routing feasibility has not been
established. Native boards use KiCad default rules; the matching SRJ declares
0.15 mm minimum trace width. These are different constraint models and should
be measured separately. An unrouted input with zero native violations is not
a successful routed result.

This directory is an optional corpus for engine development. It does not add
cases to, or change the scoring of, the frozen `benchmarks/autorouter` suite.

From the repository root, regenerate and validate:

```sh
python3 benchmarks/boards/bga-escape/generate.py
/usr/bin/python3 benchmarks/boards/bga-escape/validate.py \
  --out /tmp/bga-escape-validation --repeats 3
```

`generate.py` needs only Python's standard library. `validate.py` additionally
needs KiCad's `pcbnew` Python module and `kicad-cli` on PATH. It regenerates in
a temporary directory and requires byte-identical native/SRJ files, four copper
layers, 100 two-terminal nets, 200 front-side SMD pads, no prior routing/zones,
and matching native/SRJ pad positions, sizes and net ownership. It runs native
DRC on both bundled and regenerated boards with a 180-second per-call timeout.
Each report must include errors and warnings, have zero violations and exactly
100 unconnected items, and name each expected net exactly once. Every open must
join its two actual fixture pads, matching reference, pad number, net and position.
UUIDs must be unique within the report; they are not compared across loads because
the source files omit UUIDs and KiCad assigns them when loading.

Run the regression tests (geometry tests require KiCad’s Python module):

```sh
/usr/bin/python3 -m unittest discover -s benchmarks/boards/bga-escape -p 'test_*.py'
```

The audit rejects duplicated/missing nets, unknown/repeated pads, mixed endpoints,
incorrect positions or names, incomplete severities and native errors. This checks
input evidence only and does not change routing scores or the frozen suite.

Raw reports and `summary.csv` are written only to `--out`. A failed check raises
an error and publishes no summary. To compare an earlier fixture directory with
the same `B1/` and `B2/` layout, add `--reference /path/to/earlier/bga-escape`;
this also requires exact PCB/SRJ bytes and runs the same repeated DRC checks.

The generator and generated fixtures retain their original MIT copyright notice
in [LICENSE](LICENSE). The local generator entrypoint and parameter manifest
are adapted for this self-contained directory; generated bytes are unchanged.

To reproduce the controlled before/after audit using the fresh native reports:

```sh
/usr/bin/python3 benchmarks/boards/bga-escape/measure_report_audit.py \
  /tmp/bga-escape-validation /tmp/report-decisions.csv
```

This replays the previous count-only predicate and the stricter audit on the same
reports, plus 17 malformed variants of each report. It requires every genuine
report to pass and every malformed variant to fail the stricter audit.

The SRJ input validator accepts only the five top-level fields emitted by this
fixture generator. Added traces, vias, keepouts or rule fields fail validation
because this fixture audit does not validate their semantics. Extending the
fixture format requires extending the audit explicitly.

Nested connections, terminals, obstacles and obstacle centers also accept exactly
the fields emitted by the generator. Extra width, via, layer, port, clearance or
keepout metadata is rejected. The fixture audit does not interpret those added
constraints. `measure_nested_schema.py --before PREVIOUS_VALIDATE_PY --out CSV`
replays genuine inputs and 16 nested-field additions per tier (first and last
array entries), three times each, against both validator versions.
