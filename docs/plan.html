A headless KiCad, drawn in the browser

KiCad 10.99 ships kicad-cli api-server: the whole IPC API with no window. This plan turned that into a TypeScript web UI on Bun, a typed client covering every command, and a patch series that closed the gaps in the API itself. The board and schematic render in the browser, edits commit back to KiCad, and the whole thing is built by a roster of agents.

Architecture

Why a bridge. Browsers cannot open unix sockets. nng’s IPC framing is small enough to implement in Bun without native modules: an 8-byte \0SP\0 handshake carrying the protocol id (REQ0 = 0x30), then messages framed by a 9-byte header (type byte 0x01 plus an 8-byte big-endian length) whose body starts with a 4-byte request id. Once the fork accepts a full nng URL for --socket (G15), the browser can dial nng's built-in WebSocket transport directly and the bridge keeps only process supervision and file access.

Sessions. One bridge, many tabs, one kicad-cli api-server process per open project. This sidesteps KiCad's one-project-per-server limit without touching KiCad. Requests carry client_name = fp-pcb/<session>/<tab>, which is also how KiCad keys in-flight commits.

Document model. The page keeps a normalised item store by KIID, mutates it optimistically inside a commit, and replaces optimistic copies with the canonical items each UpdateItems returns. Undo is client-side (inverse operations replayed as new commits) until the fork gains server-side undo (G10).

The TypeScript API

Four layers, each a package, each with one owner.

LayerPackageWhat it is
0@fp-pcb/protoprotobuf-es codegen of api/proto; Any registry; int64 policy; pinned KICAD_COMMIT with a drift check in CI
1client/transportTransport interface over bytes: NngIpcTransport (Bun), WebSocketTransport (to the bridge), NngWsTransport (browser-direct after G15)
2KiCadClientenvelope, dispatch, typed errors, retry on AS_BUSY, restart detection on token mismatch; commands.ts generated from the coverage script so 100% coverage is mechanical
3object modelKiCad → Project → Board | Schematic | FootprintDocument, item wrappers keeping the original message, commit(msg, fn) with automatic drop on throw; mirrors the official Python client kipy
4client/storebrowser-only item store, indexes by type/layer/net, optimistic commits, client undo; the renderer subscribes to store diffs
const kicad   = new KiCad(await KiCadClient.connect(transport, { clientName: 'fp-pcb/abc' }));
const project = await kicad.openProject('/work/foo.kicad_pro');
const board   = await project.openBoard();

await board.commit('Move R1', async (tx) => {
  const r1 = (await board.getFootprints()).find(f => f.reference === 'R1')!;
  r1.position = mm(10, 20);
  await tx.update([r1]);            // UpdateItems → canonical item back into the store
});

Correctness is measured, not assumed: a conformance suite runs one test per command against the same api_kitchen_sink fixtures KiCad's own C++ tests use.

Drawing the design in the page

Everything needed for a faithful render is available headless: item geometry from GetItems, zone fills on the Zone message after RefillZones, pad outlines from GetPadShapeAsPolygon, and text as outlines from GetTextAsShapes, so the page never ships a font engine. Schematic symbols arrive with their library children and a transform. What is missing is drawn client-side: selection, ratsnest (until G9), DRC markers (until G4), colours (ship KiCad's default theme JSON until G11).

Renderer: WebGL2 through PixiJS v8. One container per KiCad layer in pcbnew's presentation order; an ItemView per item type; per-item rebuild on store diffs; a float64 camera feeding float32 coordinates relative to a moving origin so large boards keep precision; a spatial index for hover and pick. Targets: 60 fps pan/zoom on a 100k-item board, first paint under 2 s.

Application: React + Zustand + Vite, a three-column docked layout, a schema-driven properties panel generated from protobuf descriptors so new KiCad fields appear without UI work, and a command palette that lists every client command and, after G3, every headless RunAction. Snapshots from RunBoardJobExportSvg serve as the pixel-diff oracle for the renderer.

The UI owns selection, hover, active and visible layers, appearance and undo. That is exactly the set of commands KiCad marks GUI-only, so those need no fix.

Gaps and how each is fixed

Each gap becomes one commit on the fork's web-api branch: proto + handler + a test in qa/tests/api + a client conformance test. All written to be upstreamable.

P0G1 · Events done · PUB events socket + GetDocumentRevision

TodayREQ/REP only; nothing tells the UI a document changed.

FixPUB0 socket api-events.sock via a new KINNG_PUBLISHER; publish DocumentChanged from pushCurrentCommit, plus save/open/close and job progress. Interim: GetDocumentRevision for cheap polling.

P0G3 · Headless RunAction done · headless RunAction + GetActions

TodayGated; the headless tool manager has no tools.

FixRegister non-interactive tools on demand, the way RefillZones registers ZONE_FILLER_TOOL. Add GetActions with a headless_capable flag.

P0G4 · DRC and ERC done · DRC and ERC with markers

TodayMarker, severity and exclusion types exist; nothing runs a check or returns markers.

FixRunBoardJobDrc and RunSchematicJobErc returning markers (reuse the CLI job code paths), GetMarkers, SetMarkerExcluded, get/set severities.

P0G5 · Project and document lifecycle done · NewProject/NewDocument/GetProjectInfo + symbol documents

TodayOnly existing files open; symbol and drawing-sheet documents are rejected.

FixNewProject, NewDocument, GetProjectInfo, ListProjectFiles; a headless symbol context mirroring the footprint one.

P0G6 · Register what exists done · all three registered

FixUpdateBoardStackup gets a handler; FocusOnItem and RefreshEditor become headless no-ops; add SaveItemsToString as a selection-free clipboard export.

P0G13 · Capability discovery done · GetSupportedCommands

FixGetSupportedCommands enumerated from the registered handler tables. Trivial; makes every client future-proof.

P0G16 · Large documents done · paging, since_revision, GetItemCounts

FixPaging and since_revision on GetItems, plus GetItemCounts.

P1G7 · Libraries done · library tables, entries, get/save, wizards

FixGetLibraryTables, ListLibraryEntries, GetLibraryItem, SaveLibraryItem, CreateLibrary; ListWizards/RunWizard on the existing wizard types.

P1G8 · Schematic operations done · annotate, sync to board, fields table, sheets

FixAnnotate, SyncSchematicToBoard (today: netlist → file → ImportNetlist), BackAnnotate, schematic settings, bulk fields, sheet file creation, AssignFootprints.

P1G9 · Board operations living in tools done · ratsnest, net lengths, teardrops, autoplace

FixGetRatsnest from connectivity, net lengths, cleanup, global deletion, footprint update, teardrops, autoplace. Push-and-shove routing headless is a separate research spike.

P1G10 · Undo and redo done · Undo/Redo/GetUndoStack

FixAn undo container on the headless contexts; Undo, Redo, GetUndoStack.

P1G11 · Settings for faithful rendering

FixColour themes and app defaults, read-only first.

P1G12 · 3D

DecisionNo KiCad change: browser-side three.js on the GLB from RunBoardJobExport3D. The raytrace job needs a GPU and stays optional.

P1G15 · Transport

Fix--socket accepts any nng URL, plus --token. Browser dials ws:// directly.

P1G17 · Async jobs done · async jobs, GetJobStatus, inline outputs

Fixasync flag returning a job id, GetJobStatus, progress over G1, small outputs returned inline.

Status: every P0 gap and most P1 gaps have landed on the fork's web-api branch, 21 commits so far, each with a proto change, a handler, a QA test and a client conformance test. Colour themes and app settings (G11), the ws:// transport (G15) and the event follow-ups are the current batch. Push-and-shove routing headless stays a research spike.

Agents

Nine agents plus a coordinator, in three waves so no one waits on an unfinished interface. Each agent owns one package or concern and is judged by an objective exit test.

Wave 1 · foundations · ~1 week

Contracts and a running server

A1 · KiCad build & server

Build kicad-cli from the 10.99 checkout on macOS and in Docker; script it.

Ping and GetVersion answered from a raw-framing Bun script.

A2 · Proto & codegen

protobuf-es generation, Any registry, commit pin, and the coverage script that emits commands.json.

Reproducible bun run gen; 151 commands listed.

A3 · Transport & bridge

nng IPC framing in Bun, WebSocket bridge, one server process per session, file API.

Browser → bridge → KiCad round trip; crash detection.

Wave 2 · build · ~3 weeks

Client, renderers, first patches

A4 · Client SDK

KiCadClient, generated commands, object model, commits, conformance suite.

Every headless command green; both kitchen-sink files round-trip byte-identically.

A5 · Board renderer

Pixi scene, layer containers, item views, caches, picker, camera, theme.

Pixel-diff match with SVG export; 60 fps on 100k items.

A6 · Schematic renderer

Symbols through transforms, wires, labels, sheets, hierarchy. Starts one week after A5 on the shared core.

Matches SVG export; every pin and label pickable.

A7 · KiCad API gaps (C++)

G13, G6, G1, G5, G4 on the fork, each with proto, handler, QA test and a conformance test for A4.

Events reach a browser tab; DRC markers returned.

A8 · App shell

Layout, project screen, panels, palette, schema-driven properties, item store and client undo.

Edit, save, reopen in desktop KiCad and see the change.

Wave 3 · parity · ~4 weeks

Full design flow

A7 continued

G3, G16, G17, G7, G8, G9, G10, G11, G15.

A8 continued

Library browser, placement flows, annotate, sync to board, DRC/ERC panels, exports, 3D.

A5/A6 continued

Ratsnest, marker glyphs, routing preview, snapping.

A9 · QA & CI

Docker build of the fork, conformance + Playwright on every PR, coverage badge, larger fixtures.

Red/green in under 15 minutes on every PR.
